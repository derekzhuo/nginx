# M2: design, implementation, and validation

## Scope

M2 adds bounded, shared behavior statistics without changing M1 runtime rules or
automatically blocking requests.

Included dimensions:

- complete Referer, capped at 255 bytes;
- complete User-Agent, capped at 255 bytes;
- first normalized URI path segment as the content cluster.

Each enabled main request updates 30 ten-second buckets. The `*_qpm` variables
sum the latest 60 seconds. A 64-register HyperLogLog estimates distinct client
IPs over a five-minute tumbling window, with small-range linear counting.

## Safety decisions

### Bounded memory and key space

Statistics are present only when a shared zone is configured. The zone holds at
most 256 statistics nodes. A least-recently-used queue evicts the oldest node at
capacity, and slab allocation failure can trigger an additional eviction.

Referer and User-Agent values are truncated before indexing. URI statistics use
only the first path segment, avoiding one node per document.

### One count per client request

Directory index resolution can run the access phase again for an internal
redirect. A request-context marker was insufficient because Nginx clears module
context during that redirect. The final implementation uses a declared indexed
variable as the once-per-request marker, which survives the redirect.

### Approximate identity

The IP input is Nginx's current connection address. In the isolated test, the
official real-IP module trusts only loopback, allowing documentation-range XFF
addresses to simulate different clients. Production trust boundaries are not
part of this module.

HyperLogLog is approximate. Small ranges use the standard linear-counting
correction so a single address is reported as one instead of the empty-sketch
estimate.

### Observation, not verdicts

Statistics are exposed only through logging variables. There is no threshold or
automatic enforcement path in M2. A wave-level outlier must still be converted
into an explainable request-level rule before interception.

- `e4a0d34` — replace the tree with a bounded linear LRU index after a real
  high-cardinality failure.

## Failure investigation

The first tree-based capacity test stopped near 256 nodes. One worker waited in
`futex_wait_queue_me` and another consumed CPU. A gdb backtrace located the busy
worker in `ngx_rbtree_min()` called by the statistics eviction path.

Rather than continue with an inadequately validated tree implementation in the
request hot path, M2 removed the tree and adopted a simpler queue-only index.
Lookup is linear across at most 256 short keys. A performance review is required
before raising capacity or replacing this index again.

- Access log: worker PID, HTTP status, Referer QPM, UA QPM, path QPM, and

## Results

### Dimensions and multi-worker counts

Five identical requests produced counts 1 through 5 across two worker PIDs.
Twenty additional requests with distinct test addresses then produced:

```text

28310 200 3 3 3 1

...

```

The approximate distinct-IP value was 16 for 21 distinct addresses (including
the initial loopback client). This is an estimate, not an exact set size.

Additional branches:

| Case | Observed |
|---|---|
| Same Referer on `/eda/` | Referer and UA totals continue; path count is 1 |
| New User-Agent | UA count is 1; Referer and path totals continue |
| Missing Referer | Referer QPM and IP count are 0; UA and path continue |

### Capacity

The queue-based implementation completed 300 distinct Referers with two workers,
without a stuck request. The final old Referer started again at count 1, showing
that its previous statistics node had been evicted. The public site returned
HTTP 200 and the isolated instance was stopped afterward.

## Automated smoke harness and sanitizer evidence (2026-11-09)

`site_guard/tests/smoke.sh` replaces the manual curl sequence with a repeatable
harness. It builds a private prefix under `/tmp`, starts the already-compiled
binary on loopback port 18089, runs eight policy assertions (excluded path,
static directive, runtime rule file, unlisted and missing Referer, trailing
slash, spoof host suffix, HEAD), checks the stats variables in the guard log,
and stops the instance on exit. A 404 in the temporary prefix counts as a
pass-through because the request reached the content phase; a blocked 444
connection reports `000` from curl.

Run against the normal build:

```bash
auto/configure --prefix=/tmp/site-guard-build --add-module=./site_guard
make -j4
NGINX_BIN=$PWD/objs/nginx sh site_guard/tests/smoke.sh
```

Sanitizer run on macOS clang 21:

```bash
auto/configure --prefix=/tmp/site-guard-asan --add-module=./site_guard \
  --with-cc-opt="-fsanitize=address,undefined -fno-omit-frame-pointer -O1 -g" \
  --with-ld-opt="-fsanitize=address,undefined"
make -j4
ASAN_OPTIONS="detect_leaks=0:abort_on_error=1" \
UBSAN_OPTIONS="print_stacktrace=1" \
NGINX_BIN=$PWD/objs/nginx sh site_guard/tests/smoke.sh
```

Result: all assertions pass, and no AddressSanitizer or UndefinedBehaviorSanitizer
report contains a `site_guard` frame. One core-level UBSan report appears
without the halting option:

```text
src/core/ngx_output_chain.c:236:16: runtime error: call to function
ngx_http_trailers_filter through pointer to incorrect function type
```

This is nginx's standard filter-chain function-pointer cast, not module code.
The harness therefore fails only when a sanitizer report includes a
`site_guard` frame; core-only reports are printed as warnings. Do not enable
`halt_on_error=1` for UBSan until the core cast is handled upstream, since the
worker exits on the first response otherwise.

## Offline candidate export and historical replay (2026-11-09)

Two offline tools under `site_guard/tools/` close the candidate-rule gap
without touching production traffic. They consume only sanitized combined
logs: no cookies or credentials are parsed, and raw origin logs must not be
copied off the origin.

### Shared normalization

`sg-normalize.awk` reimplements `ngx_http_site_guard_normalize` in awk:
lowercased scheme/host, query/fragment removal, trailing-slash collapse with
root preserved, default-port stripping (https 443, http 80), bracketed IPv6
host handling, path-only inputs, and an empty result for malformed values
that the module would fail open. Both tools load it with `awk -f` so the
offline semantics cannot drift from the C implementation independently.

### candidate-rules.sh

Parses GET/HEAD requests, normalizes every Referer, and ranks canonical keys
by hits with distinct client IPs, distinct target clusters, and distinct
hosts. Cosmetic variants (uppercase, default port, query, trailing slash)
collapse onto one key, matching the module's matching behavior. `--rules`
emits at most 64 whitespace-free full-URL rules for `site-guard-ctl add`;
`--min-hits` and `--top` bound the review set.

### replay-rules.sh

Loads a rules file, normalizes each rule, and classifies every historical
GET/HEAD request exactly as the module would: no Referer passes, `-x`
excluded URI prefixes pass (prefix semantics identical to
`site_guard_excluded_prefix`), malformed Referers fail open, path-only rules
match the Referer path across hosts, and full-URL rules match the canonical
value. Per-wave output gives totals, block ratio, pass reasons, a ranked
blocked-Referer list, and a same-cluster block counter — same-cluster
navigation is the principal false-positive shape, so a non-zero count
requires human review before a rule is enforced. Passing two wave logs
prints both coverages for rule-stability comparison.

### Validation

`tests/offline-tools-test.sh` uses synthetic combined logs covering variant
collision, distinct-IP and cluster counts, `--rules` output, exclusion,
missing and malformed Referers, path-only matching, non-default-port
non-matching, and the same-cluster indicator. All 13 assertions pass under
the macOS BSD awk; the suite needs no nginx binary or network access.

### False-positive replay (FR-05)

`tests/offline-false-positive-test.sh` replays a synthetic real-reader day
against the incident fingerprint rules to prove the ruleset blocks only the
exact attack shape and never legitimate traffic. The 20 GET/HEAD lines cover
the FR-05 negative cases: no-Referer direct visits, an RSS reader,
sitemap/robots/favicon and static assets, same-cluster `/nn/` navigation
carrying a blocked Referer, an ACME `/.well-known/` renewal request, a
malformed Referer that must fail open, search-engine landings (Bing/Google),
ordinary internal cross-cluster navigation, a mobile Safari reader, a
query-string newsletter Referer, and a friendly external site. Four lines
carry the exact incident fingerprints, including one uppercase/default-port/
query cosmetic variant that must canonicalize onto the same rule and one
path-only rule exercised from a foreign host; a POST line verifies the
classifier ignores non-GET/HEAD methods.

Ten assertions check the totals: 20 classified, four blocked, and the 16
legitimate lines split into seven no-Referer, two excluded, one malformed,
and six no-rule-hit passes, with zero same-cluster blocks. The blocked list
is also checked per canonical key, so a rule that silently broadened its
match would fail the suite. The test runs entirely offline through the same
`replay-rules.sh` path and is the systematic negative-sample counterpart to
the incident-log assertions in `offline-tools-test.sh`; it does not replace
the production shadow, which still needs explicit installation authorization.

## High-rate benchmark (2026-11-09)

`tests/bench.sh` runs an isolated loopback benchmark against the plain
(non-sanitizer) build with `ab -n 20000 -k` at concurrency 1, 4, and 16.
Four scenarios share one prefix: guard off, guard on without a Referer
(fast pass), guard on with a non-matching Referer against all 64 runtime
rules (worst-case bounded linear scan), and an excluded-prefix request
carrying a blocked Referer. `ab` cannot cap request rate, so the table
reports achieved rps rather than nominal 100/1000/5000 targets.

| Scenario | c | Achieved rps | Mean ms | P95 ms | P99 ms |
|---|---:|---:|---:|---:|---:|
| off | 1 | 19176.87 | 0.052 | 0 | 0 |
| off | 4 | 39086.32 | 0.102 | 0 | 0 |
| off | 16 | 40408.20 | 0.396 | 1 | 1 |
| on, no Referer | 1 | 18925.61 | 0.053 | 0 | 0 |
| on, no Referer | 4 | 37525.78 | 0.107 | 0 | 0 |
| on, no Referer | 16 | 39102.52 | 0.409 | 1 | 1 |
| on, 64-rule miss | 1 | 18407.80 | 0.054 | 0 | 0 |
| on, 64-rule miss | 4 | 36152.18 | 0.111 | 0 | 0 |
| on, 64-rule miss | 16 | 37171.40 | 0.430 | 1 | 1 |
| on, excluded prefix | 1 | 18826.06 | 0.053 | 0 | 0 |
| on, excluded prefix | 4 | 38467.46 | 0.104 | 0 | 0 |
| on, excluded prefix | 16 | 38746.62 | 0.413 | 1 | 1 |

Two measurement caveats: macOS `ab` reports percentiles in whole
milliseconds, so P95/P99 resolution is 1 ms and sub-millisecond overhead is
judged from the mean; and loopback results exclude network and TLS cost.
Within that resolution every scenario meets the NFR (P95 <= 1 ms,
P99 <= 3 ms). At c=16 the worst-case full scan adds about 0.034 ms mean over
the guard-off baseline (0.430 vs 0.396) while sustaining above 37k rps, so
the 64-rule linear index has no measurable percentile impact on this host.

The harness also fixed a latent stop bug in both `tests/bench.sh` and
`tests/smoke.sh`: `nginx -s stop` requires the same `-c` config argument as
the start command, otherwise the signal is never sent and shutdown silently
depended on the `pkill` fallback. Both scripts now pass the config path.

## Exit assessment

M2 provides bounded cross-request observability with correct one-request
accounting, multiple aggregation dimensions, approximate IP cardinality, a
working capacity limit, an automated smoke harness, sanitizer evidence,
offline candidate-rule export with two-wave historical replay, and a
loopback high-rate benchmark meeting the latency NFR at the available
measurement resolution. Only the production shadow validation remains; it
needs at least 24 hours of shadow traffic and explicit production
installation authorization, neither of which is part of isolated testing.
