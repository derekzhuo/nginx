# M1: design, implementation, and validation

## Scope

M1 adds runtime Referer replacement without an Nginx reload while preserving the
M0 static configuration as an independent fallback.

Included:

- a named shared-memory zone;
- a local one-Referer-per-line rule file;
- atomic file publication and once-per-second change checks;
- complete parsing before generation replacement;
- previous-generation retention after invalid input or allocation failure;
- an empty-file operation to clear runtime rules;
- `$site_guard_generation` for access-log verification;
- shared-generation preservation across a graceful Nginx reload.

Still deferred: cross-IP aggregation, external management services, arbitrary
regular expressions, and automatic enforcement from statistical signals.

## Design decisions

### File-based control plane

M1 deliberately uses a local file instead of a network management API. Operators
publish a complete rule set with a temporary file and `rename`. This gives an
atomic control-plane operation without exposing a new administrative listener.

### Shared generation

Each zone has a slab pool and one shared context containing:

- generation and rule count;
- loading state and last-check time;
- file mtime, size, and inode identity;
- a fixed array of 64 shared rule descriptors.

Rule text is allocated from the slab pool. Readers hold the shared mutex only
while comparing the current generation. Static directives are evaluated
separately after runtime rules, so clearing the file cannot disable the static
fallback.

### Bounded I/O and input

A worker checks the shared last-check time before calling `stat`. At most one
worker loads a zone per second. Files are limited to 131072 bytes, 64 rules, and
2048 bytes per rule. Empty lines, whitespace, CRLF endings, and `#` comments are
handled without storing temporary data in shared memory.

### Failure behavior

The loader reads and parses the entire file in the request pool before allocating
shared rule text. If any step fails, the current generation remains usable. The
attempted file identity is recorded to avoid logging the same invalid revision
on every request. A new valid file identity is required to retry.

`passThroughOnException` is not applicable here: this is native code. Errors in
the loader return without changing the current rules, and request matching
continues against static and previous-generation rules.

## Validation environment

- Module revision: `e4773a2`;
- Nginx baseline: `release-1.30.4`;
- Workers: two;
- Shared zone: 1 MiB;
- Listener: loopback TCP port 18089;
- Dynamic rules: one per line, published with `mv`;
- Access log: worker PID, HTTP status, guard status, and generation.

## Results

| Case | Expected | Observed |
|---|---|---|
| Initial runtime rule A | A 403, B 200, generation 1 | A 403, B 200, generation 1 |
| Atomic replacement with rule B | A 200, B 403, generation 2 | A 200, B 403, generation 2 |
| Repeated requests across two workers | Same generation on both PIDs | PIDs 985 and 986 both used generation 2 |
| Invalid 65-rule file | Reject update and retain rule B | 403 and generation 2 retained |
| Empty valid file | Clear dynamic rules, generation 3 | B 200, generation 3 |
| Static fallback after dynamic clear | Static rule still blocks | 403, generation 3 |
| Restore rule B | New generation 4 | 403, generation 4 |
| Graceful reload in shadow mode | Preserve generation and do not block | 200 `MATCHED_DRY_RUN`, generation 4 |
| Master identity during file updates | No master replacement | PID 983 before and after |

Representative access-log lines:

```text
986 403 MATCHED 1
985 200 PASSED 1
985 200 PASSED 2
985 403 MATCHED 2
986 403 MATCHED 2
985 200 PASSED 3
985 403 MATCHED 3
985 403 MATCHED 4
1148 200 MATCHED_DRY_RUN 4
```

The invalid file produced the expected `exceed rule limits` error. Valid loads
produced generation 1 through 4 notices. The isolated instance was stopped after
the checks, and the public site returned HTTP 200.

## Exit assessment

M1 demonstrates that runtime policy updates do not require an Nginx reload,
that workers share one generation, and that invalid input does not create a
partial policy. M2 can build bounded behavior counters in the same zone without
changing this control-plane model.
